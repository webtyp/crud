# crud
<img src="docs/img/badges.svg">

Standard create, read, update and delete operation contract between a module's server and its screen: `ReadArgs` paging, `Cap`, `Op`, `MountCreate`, `MountRead`, `MountUpdate`, `MountDelete`.

## Why This Exists

`crud` holds the wire contract shared by a domain module's server handlers (`ops.go`) and its client screens ([`webtyp.com/view`](https://github.com/webtyp/view)) or callers ([`webtyp.com/router`](https://github.com/webtyp/router)): how a paged or ID-filtered read is requested ([`ReadArgs`](read.go), [`Cap`](read.go), [`MaxPage`](read.go)) and how records are created, read, patched, and deleted ([`CreateArgs`](args.go), [`UpdateArgs`](args.go), [`DeleteArgs`](args.go), [`MountCreate`](mount.go), [`MountRead`](mount.go), [`MountUpdate`](mount.go), [`MountDelete`](mount.go)) using [`model.Action`](https://github.com/webtyp/model) (`model.Create`, `model.Read`, `model.Update`, `model.Delete`) without `op string` parameters or generics.

| Without `crud` | With `crud` |
|---|---|
| `ListArgs`, `Cap`, `MountSave`, and `MountDelete` lived in `webtyp.com/view`, which imports `webtyp.com/dom` — so every server and Cloudflare Worker linked the browser UI kit | Servers and edge Workers import `webtyp.com/crud` (zero UI imports, enforced by [`tests/no_ui_test.go`](tests/no_ui_test.go)) and never `webtyp.com/view` |
| Every module invented `OpList*`, `OpSave*`, `OpUpdate*`, `OpDelete*` string constants and repeated `.Requires(...)` on every route | [`MountCreate`](mount.go), [`MountRead`](mount.go), [`MountUpdate`](mount.go), and [`MountDelete`](mount.go) derive `<ModelName>_c\|r\|u\|d` via [`model.Action.String()`](https://github.com/webtyp/model) and `.Requires(model.Resource(modelName), action)` automatically from [`model.ModuleNaming`](https://github.com/webtyp/model) |
| Batch saves ran record-by-record in a loop outside the module's transaction | [`MountCreate`](mount.go) passes the entire decoded `model.ModelSlice` in a single call so the module commits or rolls back the whole batch in one `db.Tx` |
| Unbounded read queries when a client sent `limit: 0` or `limit: 999999` | [`MountRead`](mount.go) and [`crud.Cap(args.Limit)`](read.go) clamp every request to `1..crud.MaxPage` (`500`) |

## Before You Start

- A record model implementing [`model.Model`](https://github.com/webtyp/model) and its list implementing [`model.ModelSlice`](https://github.com/webtyp/model) (generated by `ormc` from your `model.Definition`).
- A domain module implementing [`router.OperationModule`](https://github.com/webtyp/router) (`ModelName() string` and `MountOperations(reg router.OperationRegistry)`).
- Server packages import `webtyp.com/crud` and **never** `webtyp.com/view`.

## Step-by-Step Guide

### Step 1: Mount create, read, update, and delete operations on the server

**Goal:** Register your entity's 4 CRUD operations on `router.OperationRegistry` without `op string` constants, generics, or manual `.Requires(...)` wiring.

```go
package device

import (
	"webtyp.com/crud"
	"webtyp.com/model"
	"webtyp.com/router"
)

func (m *Module) ModelName() string { return "device" }

func (m *Module) MountOperations(reg router.OperationRegistry) {
	crud.MountCreate(reg, func() model.ModelSlice { return &DeviceList{} }, func(list model.ModelSlice) error {
		return m.CreateDevices(*list.(*DeviceList))
	})
	crud.MountRead(reg, &Device{}, func(args crud.ReadArgs) (model.ModelSlice, error) {
		rows, err := m.ReadDevices(args.ID, args.Search, args.After, args.Limit)
		return &rows, err
	})
	crud.MountUpdate(reg, func() model.Model { return &Device{} }, func(ids, fields []string, rec model.Model) error {
		return m.UpdateDevices(ids, fields, *rec.(*Device))
	})
	crud.MountDelete(reg, &Device{}, m.DeleteDevices)
}
```

**Expected result:**
- `device.device_c` (`Requires("device", model.Create)`): decodes `{"records":[…]}`, calls `m.CreateDevices` **once** with the entire batch (so `m.db.Tx` commits or rolls back atomically), and encodes the last saved record back to the caller. An empty `records` array responds `400 Bad Request` with [`crud.ErrNoRecords`](errors.go).
- `device.device_r` (`Requires("device", model.Read)`): decodes `{"id":"…","search":"…","after":"…","limit":20}`, caps `args.Limit` to `crud.MaxPage` (`500`), calls `m.ReadDevices`, and encodes `&rows`.
- `device.device_u` (`Requires("device", model.Update)`): decodes `{"ids":[…],"fields":[…],"record":{…}}`, runs `m.UpdateDevices(ids, fields, rec)`, and responds `204 No Content`. Empty `ids` or `fields` respond `400 Bad Request` with [`crud.ErrNoIDs`](errors.go) / [`crud.ErrNoFields`](errors.go).
- `device.device_d` (`Requires("device", model.Delete)`): decodes `{"ids":[…]}`, runs `m.DeleteDevices(ids)`, and responds `204 No Content`. An empty `ids` array responds `400 Bad Request` with [`crud.ErrNoIDs`](errors.go).

### Step 2: Call create, read, update, and delete from a client or test

**Goal:** Send typed requests to the mounted operations through any [`router.Caller`](https://github.com/webtyp/router) using [`crud.Op`](mount.go) and [`model.Action`](https://github.com/webtyp/model).

```go
package device_test

import (
	"webtyp.com/crud"
	"webtyp.com/fmt"
	"webtyp.com/model"
	"webtyp.com/router/loopback"
)

func ExampleClient(mod *device.Module) {
	caller := loopback.ActingAs("acme", "user-1", mod)
	op := func(action model.Action) string { return mod.ModelName() + "." + crud.Op(&device.Device{}, action) }
	check := func(err error) {
		if err != nil {
			fmt.Println(err)
		}
	}

	// 1. Read page: sends {"search":"router","after":"dev-05","limit":20}
	var list device.DeviceList
	caller.Call(op(model.Read), &crud.ReadArgs{Search: "router", After: "dev-05", Limit: 20}, &list, check)

	// 2. Create batch transactionally: sends {"records":[{"name":"Core Switch"}]}
	var saved device.Device
	caller.Call(op(model.Create), &crud.CreateArgs{
		Records: []model.Model{&device.Device{Name: "Core Switch"}},
	}, &saved, check)

	// 3. Update specific fields across rows: sends {"ids":["dev-01"],"fields":["name"],"record":{…}}
	caller.Call(op(model.Update), &crud.UpdateArgs{
		IDs: []string{saved.ID}, Fields: []string{"name"}, Record: &device.Device{Name: "Core Switch v2"},
	}, nil, check)

	// 4. Delete by IDs: sends {"ids":["dev-01"]}
	caller.Call(op(model.Delete), &crud.DeleteArgs{IDs: []string{saved.ID}}, nil, check)
}
```

**Expected result:** Each call resolves the canonical operation name via `crud.Op(&device.Device{}, model.Read|Create|Update|Delete)`, serializes the wire JSON, and decodes the server's response into `&list` or `&saved`.

### Quick Reference

| I want to… | Use |
|---|---|
| Build the canonical operation name of a model | `crud.Op(m, model.Create \| model.Read \| model.Update \| model.Delete)` ([`mount.go`](mount.go)) |
| Mount a transactional batch create operation | `crud.MountCreate(reg, newList, create)` ([`mount.go`](mount.go)) |
| Mount a capped read operation | `crud.MountRead(reg, &Model{}, read)` ([`mount.go`](mount.go)) |
| Mount a field-patch update operation | `crud.MountUpdate(reg, newRecord, update)` ([`mount.go`](mount.go)) |
| Mount a batch delete-by-IDs operation | `crud.MountDelete(reg, &Model{}, remove)` ([`mount.go`](mount.go)) |
| Cap a page limit manually to `1..500` | `crud.Cap(args.Limit)` ([`read.go`](read.go)) |
| Send a create batch from a client | `caller.Call(op, &crud.CreateArgs{Records: recs}, out, done)` ([`args.go`](args.go)) |
| Send a multi-row field patch from a client | `caller.Call(op, &crud.UpdateArgs{IDs: ids, Fields: cols, Record: rec}, nil, done)` ([`args.go`](args.go)) |
| Send a delete-by-IDs call from a client | `caller.Call(op, &crud.DeleteArgs{IDs: ids}, nil, done)` ([`args.go`](args.go)) |
